# Goravel Inertia — v1.18.0

This skill targets [`github.com/goravel/inertia` v1.18.0](https://github.com/goravel/inertia/tree/v1.18.0), not an unspecified later release. It uses Inertia.js v3 through `github.com/petaki/inertia-go` v1.15.0. The tagged `go.mod` requires Go 1.26.1 and Goravel framework v1.18.0; the frontend needs Node 18+. Check the installed versions before applying this guidance. Read [inertia-v3.md](inertia-v3.md) for the protocol; the installed adapter's implementation determines its actual behavior.

## Workflow

1. Inspect `go.mod`, providers, web routes, session middleware, `config/inertia.go`, the root template and frontend entry. Respect the project's existing setup and command execution rules.
2. Put session middleware before Inertia middleware on the web routes. Keep API routes separate. Use the application's shared-props callback for request-specific data, exposing only fields safe to send to the browser.
3. Register request props before `Render` on the same context. Match the component name and serialized prop shape to the client page resolver.
4. Return redirects after mutations; bridge validation errors and flash through the session. Use `Location` for external visits.
5. Test the HTTP boundary with real Inertia headers, including stale asset versions, redirects, validation and flash; verify the frontend build when its entry or assets change.

## Setup and frontend

The [v1.18.0 README](https://github.com/goravel/inertia/blob/v1.18.0/README.md) documents `go run . artisan package:install github.com/goravel/inertia`, which registers the provider in `bootstrap/providers.go` or `config/app.go`. Pin the dependency to v1.18.0 using the project's dependency workflow; verify the resulting `go.mod`.

`go run . artisan inertia:install` scaffolds Vue 3; `--stack=react` selects React. It creates configuration, a root template, frontend entry, demo controllers and routes, and `app/http/middleware/handle_inertia_requests.go`. Inspect existing files first: the command wires routes and removes the default welcome view; `--force` overwrites files. Svelte is not a scaffolded option.

In v1.18.0, Vite settings belong to `config/inertia.go`: `vite.public_path`, `vite.build_dir`, `vite.hot_file`, and `vite.dev_url`. The root template helper `{{ vite "resources/js/app.ts" }}` chooses the hot file, then `VITE_DEV_URL`, then the build manifest. Do not substitute configuration from a newer adapter release. Asset version defaults to the manifest hash; `INERTIA_VERSION` pins it explicitly.

## Rendering and props

The tagged README imports `github.com/goravel/inertia/facades`:

```go
facades.Inertia().Defer(ctx, "stats", func() any { return loadStats() })
return facades.Inertia().Render(ctx, "Home", map[string]any{"message": "Hello"})
```

Use middleware `share(ctx)` or `ShareFunc` for request-dependent shared values; `Share` is static and registered at boot. Explicit render props override shared props with the same key. Never place credentials or unrestricted user records in shared props.

`inertia:install` writes the app-owned wrapper below (imports: `contracts/http`, the framework `facades`, and `inertiamw "github.com/goravel/inertia/middleware"`); the protocol stays in `inertiamw.Handle`, so keep the wrapper and edit only `share()`:

```go
// app/http/middleware/handle_inertia_requests.go
func HandleInertiaRequests() http.Middleware {
	return inertiamw.Handle(inertiamw.Options{Share: share})
}

func share(ctx http.Context) map[string]any {
	return map[string]any{
		"appName": facades.Config().GetString("app.name"),
		"auth":    map[string]any{"user": authUser(ctx)},
	}
}

func authUser(ctx http.Context) any {
	if !ctx.Request().HasSession() {
		return nil
	}
	return ctx.Request().Session().Get("user")
}
```

Register it after `sessionmiddleware.StartSession()` on the web group. `share` runs once per request and each entry becomes a per-request prop. Inertia is session-based: persist the user with `ctx.Request().Session().Put("user", user)` at login and `Forget("user")` at logout.

Available request helpers include `Prop`, `Defer`, `Optional`, `Always`, `Merge`, `DeepMerge`, `Prepend`, `Scroll` and `Once`. Register them before rendering; verify exact callback types and options against the installed package when using them.

## Session, redirects and validation

The middleware bridges configured session flash keys to `props.flash` and validation errors to `props.errors`; read them there, not as top-level page flash. `Flash(ctx, data)` sets the whole `props.flash` map, so a later call replaces it.

Validator construction can fail and leave `validator` nil, so guard `Errors()`. The generated controller shows the exact flow; import the package's facades as `inertiafacades` when the file also imports the framework facades:

```go
// app/http/controllers/contact_controller.go
func (r *ContactController) Store(ctx http.Context) http.Response {
	validator, err := ctx.Request().Validate(map[string]any{
		"name":  "required|min_len:2",
		"email": "required|email",
	})
	if err != nil || validator.Fails() {
		if validator != nil {
			inertiafacades.Inertia().FlashErrors(ctx, validator.Errors())
		}
		return inertiafacades.Inertia().Redirect(ctx, "/contact")
	}

	ctx.Request().Session().Flash("success", "Saved")
	return inertiafacades.Inertia().Redirect(ctx, "/contact")
}
```

`err != nil || validator.Fails()` short-circuits before the nil validator is used. `validator.Errors()` returns `validation.Errors` (`All()`, `One(field)`); `FlashErrors` stores one message per field in the session, and `ShareSession` exposes them as `props.errors` on the redirected GET. Flash keys default to `success`, `error`, `warning`, `info`, `message` and are configurable with `inertia.flash_keys`. `Redirect` returns 303 after PUT/PATCH/DELETE and 302 otherwise; `Location` requests a full-page visit for an Inertia request.

On flash the adapter wins over the protocol: read `props.flash`, not the protocol's top-level `flash` field. Precognition is not implemented in v1.18.0: a request carrying `Precognition: true` reaches the handler like any other, so add a guard that answers 204/422 before it, or leave the client feature off.

## Versioning, SSR and verification

The middleware compares the incoming asset version on Inertia GET requests and returns 409 with `X-Inertia-Location` on a mismatch. Non-GET requests do not perform this version check. Check the installed implementation when asserting additional headers or flash preservation.

SSR is configured with `ssr`, `ssr_url` and `ssr_timeout`; the adapter falls back to client-side rendering if the SSR server is unreachable. Exercise both success and fallback if enabling SSR.

At the HTTP seam, send `X-Inertia: true` with the current version and assert the page object. A GET whose `X-Inertia-Version` differs from `facades.Inertia().Version()` — including an empty header against a non-empty version — is answered 409, so always send it:

```go
// tests/feature/users_test.go, in a suite embedding tests.TestCase
func (s *ExampleTestSuite) TestUsersPage() {
	version := inertiafacades.Inertia().Version()
	resp, err := s.Http(s.T()).
		WithHeader("X-Inertia", "true").
		WithHeader("X-Inertia-Version", version).
		Get("/users")
	s.Require().NoError(err)
	resp.AssertOk()

	page, err := resp.Json()
	s.Require().NoError(err)
	s.Equal("Users/Index", page["component"])
	s.Equal("/users", page["url"])
	s.Equal(version, page["version"])
	s.Equal("hello", page["props"].(map[string]any)["message"])
}
```

`s.Http` drives the real router and session; `WithSession(map[string]any{"success": "Saved"})` seeds flash for a `props.flash` assertion. Also cover a plain HTML visit (no `X-Inertia`), a stale version expecting 409 with `X-Inertia-Location`, a mutation redirect (303 after PUT/PATCH/DELETE) and `props.errors` after a failed submit. Follow the project's container-only development rules where applicable.
